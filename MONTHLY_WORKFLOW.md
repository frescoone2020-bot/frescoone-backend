# Monthly Finance Workflow

How to keep this system running every month, and how it gets more useful the longer you run it.

## 1. Each month, drop in the new files (same names/patterns as this month)

| What | Where | Naming |
|---|---|---|
| SKU master (if prices/costs changed) | project root | `*isku*table*data*.xlsx` (overwrite the existing file) |
| SiteGiant order export | project root | `from-sitegiant-Orders_*.zip` (delete/replace last month's zip) |
| Reseller invoices | `dropship-reseller-file/` | `INV-LCON*.xlsx`, `INV-SCON*.xlsx`, `INV-SSUP*.xlsx` (overwrite) |
| Bank statement | project root | `*ocbc*.csv` or `e-Statement*.csv` — **export the full statement each time, not just the new month**, since 13 months of history feeds the cash flow trend and YoY growth chart |
| Payroll payslips | `past-6months-payroll-history/` | new month's zip added; old ones can stay or be pruned once `history/` has captured them |
| Platform fee/income reports (optional, but adds real fee data) | `income-exported-SiteGiant D2C/{lazada,shopee,tiktok}/` | Export each **FRESCOONE-branded** storefront's income/balance/fee report from its own seller centre: Shopee "Balance Transaction Report", TikTok "Income" export (needs Order details + Withdrawal records sheets), Lazada finance CSV. Requires re-entering your platform login password (a security step-up), which I can't do for you -- you export these yourself. Without this folder, D2C revenue stays gross of platform fees. |
| Raw marketplace order exports (optional) | `order-exported-SiteGiant D2C/{shopee,tiktok,lazada}/` | Each connected storefront's own bulk order export (Shopee "Order.all...xlsx", TikTok "All order...csv", Lazada order xlsx) -- one file per storefront, including non-FRESCOONE-branded ones (DUX, Justincase, etc.) that don't have a dedicated fee report. Shopee's own order export includes Transaction Fee/Commission Fee/Service Fee columns directly, so this is the only way to get real fee data for those other storefronts. Rename files to note which storefront they're from (e.g. `DUX-Order.all...xlsx`) since the platform's own filenames don't say. Auto-matched to the correct SiteGiant marketplace by order-ID overlap, not filename. |
| Cost overrides (optional, generated by you) | project root | `cost_overrides.json` -- see Section 5 below. Not something you create from scratch; it's downloaded from the dashboard's Pending Action table. |

The script auto-discovers files by pattern, so exact filenames can change month to month (dates, invoice numbers, etc.) as long as the pattern still matches.

## 2. Run it

```
pip install pandas openpyxl pdfplumber      # once, or after a Python reinstall
python finance_analyzer.py
```

## 3. What comes out

- `Executive_Financial_Report.md` — narrative report for this run's period, overwritten each time.
- `dashboard.html` — open it in any browser (double-click it). Overwritten each time.
- `history/<month>.json` — **never overwritten across months** (only re-running the *same* month overwrites that month's file). This is what turns single-month snapshots into a real trend.

## 4. Why the trend line looks thin right now

The "Accrual Revenue & Net Profit Trend" chart only has one point (June 2026) because that's the first month run. It is **not** the same as the cash flow chart above it — that one already spans 13 months because your bank statement export covers that much history in one file. The accrual trend has no equivalent shortcut: SiteGiant and the reseller invoices are only ever exported for one month at a time, so each monthly run adds exactly one point. After 3-4 months of runs, that chart starts actually showing MoM movement; after 12+, real YoY.

**Don't delete files from `history/`** — that folder is the only place multi-month accrual truth accumulates. Back it up like you would the source data.

## 5. Things worth tightening over time

These are flagged in the report's "Known Scope Limitations" section every run, but worth acting on when you have time:

- **Missing SKU costs -- now fixable from the dashboard.** Open `dashboard.html` -> Order Detail tab -> scroll to "Pending Action" -- every SKU with no match in the SKU master is listed there (aggregated across all its orders), with an input box to key in the correct cost per unit. Click "Download cost_overrides.json" and save that file into this project folder (same folder as `finance_analyzer.py`). Next run, `python finance_analyzer.py` picks it up automatically (you'll see "Applied N manually keyed-in cost override(s)" in the output) and those SKUs resolve like any other -- no need to touch the SKU master `.xlsx` directly. Still worth adding genuinely new products to the real SKU master eventually, but this closes the gap immediately without waiting.
- **"Bank Statement OpEx" is a catch-all**: right now everything that isn't payroll or the director loan gets lumped into one "Vendor / Other Payment" bucket. If you want a real OpEx-vs-COGS split (e.g. separating freight/packaging from true overhead), that requires either tagging vendors in the bank statement or telling me which recurring counterparties should be reclassified — I can add rules to the categorizer in `finance_analyzer.py` (`BANK_CATEGORY_RULES`).
- **Platform commission/payment-processing fees** are captured for FRESCOONE Shopee/Lazada/TikTok (via `income-exported-SiteGiant D2C/`) and for any other storefront covered by its own raw order export (`order-exported-SiteGiant D2C/`) -- currently DUX and Justincase Shopee. Any storefront not covered by either is still gross of fees.
- **CASEON SG and FRESCO SG (Singapore storefronts) are excluded from every RM figure entirely** — their order amounts are in SGD, not MYR, and no exchange rate has been confirmed yet. They're reported separately in SGD on the Overview tab. Give me a conversion rate (or tell me where to source one) when you're ready and I'll fold them into the RM totals properly.

## 6. If something breaks

New months' files won't always look identical to what the parser expects (a reseller adds a column, a payslip template changes, etc.). If the script errors out or a number looks wrong, tell me what changed and I'll fix the relevant parser function rather than you needing to touch the code yourself.
